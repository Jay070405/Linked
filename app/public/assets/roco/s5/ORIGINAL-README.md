# S5 双方案：简单交互原型

## 体验

打开页面即进入 A 活动主页，顶部可切换 B。导览预置 A 24 音符、B 足迹116与叫声120；捕捉一次即可进入下一阶段。演示设置可选择普通、异色、污染、临近保障或超时。

- A：前往捕捉 → 投球 → 返回音乐会 → 演奏 → 左侧攻击3次 → 揭晓 → 捕捉 → 返回。
- B：收集线索 → 组合两种线索 → 进入调查 → 点击三个任务地点 → 选择奖励 → 破罩捕捉。
- 自由体验：顶部重新开始 → 从零体验。此操作只重置本机原型。

## 界面与表现

采用16:9色块原型。活动标题靠左、精灵居中、活动入口靠右、功能入口在底部；攻击操作置于战斗左侧。参考实机信息分区，不是官方界面的像素级复刻。A用音符汇入和分层定音，B用定位声源、取景拍照和调查归档区分操作。

活动布局参考作者提供的S3「铅字幻梦」截图。战斗布局参考：https://shouyou.3dmgame.com/gl/616983.html （页面内实际游戏截图）。未将第三方完整截图嵌入原型。

乐章预览不抽取结果。攻击3次破罩后按血脉、特长、外观揭晓；跳过和重播不改变结果。污染演示独立于普通乐章和保障。

2026-09-05 表现更新：投球弧线、命中光圈、破罩碎片、音符汇入与乐章就绪反馈；A三声部音环、B档案扫描与取景归档；结算入场和按钮按压反馈。投球期间短暂防连点，逻辑即时提交、不延迟结算或重抽。装饰动效遵循系统“减少动态效果”，不承担唯一的信息提示；概率与保障配置未改变。

## 配置与边界

规则在 lib/game.ts，存档在 lib/storage.ts，界面在 app/simple-prototype.tsx，样式在 app/globals.css、app/play.css 和 app/review.css。
三只示例目标：稻草人、守夜烛、栗鼠。目标按单只精灵与形态绑定，奖励目标与有效来源名单分别配置。区域和捕捉难度档是原型示例，不是官方地图或捕获率。特长固定展示“灵巧”，不模拟其分布；它与“守望者”等精灵特性不是同一字段。所有捕捉采用演示成功／失败开关；异色随机按提案运行。预设及预置进度不作为随机统计。

A：28音符；普通物种池70/20/10，基础异色5%，第61次起每次＋0.5个百分点，第80次指定目标异色。
B：线索120、非捕捉最多60；六组合；任务40/30/30；12分钟；外观路线第四轮保障。简化版演示核心循环，未制作完整战斗、角色移动、配音或额外星夜协奏子玩法。

## 本地运行

安装 Node.js 22.16 或兼容22版本，在此目录执行 npm ci，再执行 npm run dev。浏览器访问 http://localhost:3000。

Windows Node24环境下本框架构建退出阶段可能触发libuv断言；已使用以下命令验证成功：

```
npm exec --yes --package=node@22.16.0 -- node node_modules/vinext/dist/cli.js build
node --experimental-strip-types --test tests/game.test.mjs tests/storage.test.mjs
npx tsc --noEmit
```

24项自动化测试覆盖来源、余量、队列上限、目标独立、保障、6条调查路线、超时、重复结算、失败、演示统计隔离、揭晓保密及存档升级。浏览器实测走通两案导览和从零体验、六条调查路线及三类奖励。自测仅证明原型规则和操作可运行，不代表玩家已认可玩法或正式游戏平衡已验证。
